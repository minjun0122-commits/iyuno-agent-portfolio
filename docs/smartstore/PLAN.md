## 4. 가격·마진 규칙

```
판매가 = 총원가 ÷ (1 − 수수료율 − 목표마진율)   → 100원 단위 올림
마진율 = (판매가 × (1 − 수수료율) − 총원가) ÷ 판매가
```

- 수수료율 5.63%(네이버페이 주문관리 최대 3.63% + 네이버쇼핑 매출연동 2%). 판매자센터 정산 내역으로 실제 요율을 확인할 것
- 목표마진 **20%**, 최소마진 5%
- 바디필로우: 총원가 12,480원, 판매가 19,900원 → 수수료를 빼면 **마진 약 31.7%** (37%는 수수료를 빼기 전 수치)
- 미니 화병: 원가 6,670원 → 12,900원이면 수수료를 빼도 약 43%
- 자동화 동작: **직접 정한 가격이 목표마진을 넘으면 그대로 둔다.** 원가가 올라 목표마진을 밑돌 때만 가격을 올린다(자동으로 내리지는 않음). 최소마진도 안 되면 재고를 0으로 둔다.

## 5. 자동화: n8n → 이 코드로 무료 이전

### 무엇을 켜나
| 작업 | 지금(주문 0건) | 첫 주문 이후 |
|---|---|---|
| `sync-inventory --notify` | **켬 (1시간마다)** — 오너클랜 재고 → 네이버 옵션별 재고, 재입고·품절 메일 | 계속 |
| `sync-orders --notify` | dry-run으로 켬 (10분마다) — 신규 주문이 생기면 메일만 발송 | `--apply`로 발주확인 + 오너클랜 발주서 자동 생성 |
| `sync-tracking` | 끔 | `--apply` (30분마다) |
| `draft-cs` | 하루 2회, 초안만 | 검토 후 `--post` |

### 설치 순서 (오라클 클라우드 Free Tier)
1. Always Free VM(Ubuntu) 생성 → **VM 공인 IP를 커머스API센터 애플리케이션의 허용 IP에 등록**
   (커머스API는 등록된 IP에서 온 호출만 받는다. 그래서 이 VM이 필요하고, Claude 세션에서는 직접 호출할 수 없다)
2. 설치
   ```bash
   git clone <이 레포> store && cd store
   python3 -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt
   mkdir -p data/smartstore logs && cp examples/smartstore/*.csv data/smartstore/   # <...> 칸을 실제 값으로 채우기
   ```
3. `~/.store.env` (레포에 커밋 금지)
   ```bash
   export NAVER_COMMERCE_CLIENT_ID=...
   export NAVER_COMMERCE_CLIENT_SECRET=...
   export SMARTSTORE_SMTP_HOST=smtp.gmail.com
   export SMARTSTORE_SMTP_USER=...@gmail.com
   export SMARTSTORE_SMTP_PASSWORD=...      # Gmail "앱 비밀번호"
   export SMARTSTORE_NOTIFY_TO=...@gmail.com
   ```
4. 먼저 dry-run으로 응답 확인
   ```bash
   . ~/.store.env && python -m smartstore.jobs sync-inventory
   ```
   → 옵션명(핑크/그레이/브라운)이 `product_map.csv`와 일치하는지, 가격·재고 변경 계획이 맞는지 확인한 뒤 `--apply`
5. crontab (먼저 `sudo timedatectl set-timezone Asia/Seoul`로 VM 시간대를 한국 시간으로 맞춤)
   ```
   7 * * * *     cd ~/store && . ~/.store.env && .venv/bin/python -m smartstore.jobs sync-inventory --apply --notify >> logs/inv.log 2>&1
   */10 * * * *  cd ~/store && . ~/.store.env && .venv/bin/python -m smartstore.jobs sync-orders --notify >> logs/orders.log 2>&1
   5 9,21 * * *  cd ~/store && . ~/.store.env && .venv/bin/python -m smartstore.jobs draft-cs --apply --notify >> logs/cs.log 2>&1
   ```
6. 확인이 끝나면 n8n 체험판은 자연 만료되게 둔다

### 오너클랜 연동 방식
- `supplier_inventory.csv`: 오너클랜에서 내려받은 상품 재고·가격을 SKU 단위로 옮겨 둔 파일
  (지금은 수동 갱신이고, n8n에서 쓰던 오너클랜 연동을 옮기려면 공급사 연결 부분만 새로 만들면 된다)
- 첫 주문 이후 `sync-orders --apply`를 켜면 `supplier_orders_outbox.csv`(오너클랜 대량발주 양식용)가 만들어진다 → 업로드한 뒤 **파일 삭제**(수취인 개인정보)
- 송장은 오너클랜에서 받아 `supplier_tracking.csv`에 넣으면 `sync-tracking`이 네이버 발송처리를 한다

### 파일 매핑 (`product_map.csv`)
```
origin_product_no,sku,option_name
<바디필로우 원상품번호>,<핑크 SKU>,핑크
<바디필로우 원상품번호>,<그레이 SKU>,그레이
<바디필로우 원상품번호>,<브라운 SKU>,브라운
<양념통 원상품번호>,<양념통 SKU>,
```
`option_name`은 네이버 옵션명과 글자까지 똑같아야 한다(옵션이 2단이면 `핑크/90cm`처럼 `/`로 잇는다). 맞지 않으면 쓰지 않고 알림만 보낸다.

## 부록: API 스펙 확인 필요

코드는 커머스API 문서 구조를 기준으로 작성했지만, **실제 계정으로 한 번도 호출해 보지 않았다.**
첫 실행은 반드시 dry-run으로 하고, 특히 다음 항목은 응답을 직접 확인할 것:
원상품 조회의 `detailAttribute.optionInfo.optionCombinations` 필드명, 주문 `last-changed-statuses`·`query`·`confirm`·`dispatch`, 문의 `contents/qnas`.
택배사 코드(`deliveryCompanyCode`)는 문서의 코드표를 쓴다.
